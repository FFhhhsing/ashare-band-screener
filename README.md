# A股波段买点 · 云端自动筛选

每天 **15:10（收盘后）** 自动跑，完全不依赖你的电脑是否开机。
结果推送到微信，点开是带交互式 K 线图的完整报告。

- 行情数据：东方财富 / 腾讯公开接口（双源自动降级）
- 报告托管：GitHub Pages，手机浏览器直接打开
- 推送渠道：Server酱 或 PushPlus（微信）

---

## 它解决了什么问题

之前定时任务跑在本机 WorkBuddy 里，依赖 macOS 定时唤醒。实测你的电脑 `sleep 34`（空闲半小时就睡），14:28 的 `wakepoweron` 并没能真正把机器叫醒（当日唤醒日志里最后一次是 19:47 因「开盖」触发），任务自然跑不了。

本机唤醒这条链路要过三关：定时唤醒是否生效 → 唤醒后能否维持足够久 → WorkBuddy 是否开机自启。任一环断掉就失败，且和 macOS 电源管理强耦合，不可靠。

**现在改为：GitHub 的服务器替你跑，跑完把结果推到手机。你的电脑关机、合盖、断网都不影响。**

## GitHub Actions 是什么？

一句话：**GitHub 免费借给你的一台"一次性电脑"**。

你把代码放进 GitHub 仓库，再写一份 `daily.yml` 说明「什么时候跑、跑什么」。到点了，GitHub 就在自己的服务器上开一台 Linux 机器，把代码下载下来、装好 Python 依赖、执行脚本，跑完机器直接销毁。

它和"定时任务跑在你电脑上"的区别：

| | 跑在你电脑上 | GitHub Actions |
|---|---|---|
| 电脑要开机吗 | 要，还得能被唤醒 | 不需要，关机合盖断网都不影响 |
| 漏跑的原因 | 休眠、断网、客户端没启动、电源管理 | 几乎没有（GitHub 自己的服务器） |
| 成本 | 电费 + 机器占用 | 公开仓库 Actions 免费且不限量 |
| 结果在哪看 | 本机文件 | 微信推送 + 网页报告 |

公开仓库 Actions 免费且不限量，本项目单次约 15 分钟，完全在免费范围内。

> 注意：GitHub 的定时任务**通常有 5–15 分钟延迟**，设的是 15:10，实际 15:15–15:25 收到都正常。

## 十分钟配置步骤

### 第 1 步 · 建仓库

1. 打开 https://github.com/new
2. 仓库名填 `ashare-band-screener`，选 **Public**（公开）
3. 取消勾选 "Add a README file"（代码已自带 README），点 Create repository

### 第 2 步 · 上传文件

把本目录下这些内容原样传到仓库根目录（可以直接拖拽上传）：

```
screener.py
requirements.txt
.github/workflows/daily.yml      ← 注意 .github 是隐藏目录，要整个拖进去
```

`state/` 目录不用上传，脚本首次运行会自动创建（里面是观察池记录）。

> 如果网页上传不方便建隐藏目录，也可以在仓库页面点 `Add file → Create new file`，
> 文件名直接填 `.github/workflows/daily.yml`，GitHub 会自动建目录。

### 第 3 步 · 拿微信推送 key

**方式 A：Server酱（推荐）**
1. 打开 https://sct.ftqq.com/ ，微信扫码登录
2. 复制 `SendKey`（形如 `SCT123456xxxxx`）
3. 页面下方点「消息通道」→ 确认已绑定你的微信

**方式 B：PushPlus**
1. 打开 https://www.pushplus.plus/ ，微信扫码登录
2. 首页复制你的 token

### 第 4 步 · 填 Secret

进入仓库 → `Settings` → `Secrets and variables` → `Actions` → `New repository secret`

| Name | Value |
|---|---|
| `PUSH_KEY` | 第 3 步拿到的 SendKey 或 token |
| `PUSH_CHANNEL` | 用 Server酱填 `serverchan`；用 PushPlus 填 `pushplus` |

### 第 5 步 · 开启 GitHub Pages

1. 仓库 → `Settings` → `Pages`
2. Source 选 **Deploy from a branch**
3. Branch 选 **gh-pages**，目录 `/ (root)`，点 Save

> 第一次要等任务跑过一次之后 `gh-pages` 分支才会出现。
> 可以先做完第 6 步手动跑一次，再回来选分支。

### 第 6 步 · 手动跑一次验证

仓库 → `Actions` → 左侧选 `A股波段买点每日筛选` → 右上角 `Run workflow` → 再点绿色按钮。

约 15 分钟后：微信收到推送消息，点链接能看到 K 线图报告。

## 三个买点的判定规则（收盘口径）

| 买点 | 条件 |
|---|---|
| **买点1 突破转势** | 收盘价 > 布林上轨 或 创 20 日新高；MA5 > MA10；MA20 走平或向上；DIF > DEA；成交量 > 5日均量 ×1.5；当日收涨 |
| **买点2 回踩不破** | 20 日涨幅 > 10%；**最低价 ≥ MA20**（未破线）；收盘 > MA20；成交量 < 5日均量（缩量）；当日 -5% ~ +2%；换手 2%-15% |
| **买点3 破线拉回** | **最低价 < MA20** 且 **收盘价 > MA20**；振幅 > 3%；换手 2%-15%；当日收涨 |

统一剔除：ST/*ST/退市、北交所、流通市值 30 亿以下或 800 亿以上、换手率 < 1%。

评分维度：技术面 40 + 资金面 20 + 动量 15 + 乖离 6 + 量能配合 6 + **估值 8** + 买点类型 10 − **亏损惩罚 5**（若适用）。
其中买点2 给满分 10 分，因为它的止损位就在 MA20 脚下，风险收益比最好。

**乖离为什么按买点分档？**
早期版本一律「`|bias20|` 越小越好」。这是个陷阱：买点2 的定义就是**回踩**，而回踩必然压低 20 日涨幅和乖离率，于是真正的好回踩分数反而低于正在冲高的票——**系统在结构上优先留下冲高票、淘汰回调到位的票**，与买点2 的本意完全相反。
现在买点2 改为：`bias20` 落在 **0 ~ 3%**（贴着 MA20 的教科书位置）给满分 6 分，再远逐级递减，超过 10% 视为追高给 0 分。买点1 刚突破、正乖离本就正常，标准放宽到 8%。

**亏损股怎么处理？（分层，不一刀切）**

| 类型 | 处理 |
|---|---|
| `PE ≤ 0` 且 `PB > 5`（又亏又贵） | **硬剔除**，不进任何名单 |
| `PE ≤ 0` 且 `PB ≤ 5`（跌透的周期底部股） | 保留资格，**扣 5 分** |
| `PE` 数据缺失 | 不剔除也不扣分（数据缺失 ≠ 亏损） |

为什么不直接全部剔除？地产、养殖、光伏、券商在周期底部普遍 TTM 亏损，而这类恰恰是波段弹性最大的品种；一刀切等于每次都在底部把它们排除。而且 `PE` 用的是滚动 12 个月的动态市盈率，Q2 刚扭亏的公司 TTM 仍可能为负，会被误杀。
至于真正的高危（ST/退市），在粗筛阶段就已按名称过滤掉了，不会进池子。

**估值为什么只占 8 分，且用分位而不是绝对值？**
早期版本给估值 20 分，并用 `PE ≤ 35` 作为满分线。实测发现这是系统性偏见：全市场 PE 中位数是 **40.3**，而半导体、软件这类行业的中枢在 80–150，用 35 的线去卡等于把整个行业判死刑——国产模拟芯片龙头思瑞浦（PE 117）曾因此被扣 17 分、掉到第 18 名，而造纸股因为 PE 15.8 拿了满分排第一。

现在改为 **PE 全市场分位**：只要一只票在自己的估值分布里不算极端就不扣分（P20 以内 6 分，P20–40 得 5 分，以此类推）。省下的 12 分补给两个连续型指标——**乖离率**（离 MA20 越近风险越小）和**量能配合**（买点1/3 看放量、买点2 看缩量）。

这么改还有一个额外好处：连续型指标能撑起区分度。实测如果彻底去掉估值分，买点1 会出现 **13 只并列 79 分**抢 8 个名额，排名失去意义。

**同分怎么排序？**
按 `分数 → 乖离率绝对值小者优先 → 代码` 三级裁决。因为历史数据是并发拉取的，若不显式指定顺序，同分名单每次跑出来都不一样、不可复现。

## 观察池与回访区

**要解决什么问题？**
系统原本是**无状态每日快照**：某票 D 日出现在买点1 榜单 → 回调几天 → 又满足买点2 条件，但**排名掉出前 15** → 它就在报告里彻底消失了。

而"回踩到位"恰恰会压低动量和乖离分，跟"排进前 N 名"是**负相关**的——所以这个缺陷不是偶发，而是系统性的。

**怎么解决？**
进过榜的票会被记进 `state/watchlist.json`，之后每天**单独复算**：

- 即使当天排名掉出名额，只要它仍在观察池里且再现买点信号，就会进 **回访区**（不占 15 个名额，最多展示 6 只）
- 卡片上会标注：`09-11 曾以 买点1 入选（¥12.34），至今 −6.2%，今日再现 买点2`
- 观察期约 **20 个交易日**；期间**跌破 MA60** 或**跌破入选价 −10%**（趋势已坏）提前移出

**为什么观察池要提交回仓库？**
GitHub Actions 每次运行都是全新 checkout，工作目录下的任何文件跑完就丢。所以 `daily.yml` 里有一步把 `state/watchlist.json` 自动 commit 回去——**少了这一步，观察池每天都会被清零，回访区永远出不来**。

报告底部的「备选」区是另一层兜底：把各买点第 16 名之后的紧邻名次列成简表，成本为零，避免"明明进了候选池却因为名额被藏起来"。

## 常见问题

**Q：GitHub Actions 免费吗？**
GitHub 个人账号对**公开仓库提供免费且不限量**的 Actions。**实测单次约 15 分钟**（默认 `POOL_SIZE=1200`；若设为 0 跑全量 1961 只则需约 24 分钟），每月 20 个交易日约 300 分钟，完全免费。

**Q：为什么不用同花顺 iFinD 的数据？**
因为 iFinD、通达信、腾讯自选股这些**连接器都跑在你本机的 WorkBuddy 客户端里**，云端服务器连不到——换哪个连接器都一样，这是架构决定的，不是配置问题。
云端只能用**公开行情接口**（本项目）或 **Tushare 这类 HTTP API + token** 的服务。

**Q：数据源是什么？会断吗？**
做了双源自动降级，不会因为单一接口挂掉就失效：

| 用途 | 首选 | 兜底 |
|---|---|---|
| 全市场快照 | 东方财富 `stock_zh_a_spot_em` | 腾讯 `qt.gtimg.cn` 批量行情（穷举代码，实测命中 4596 只） |
| 个股日线 | 腾讯 `stock_zh_a_hist_tx` | 东方财富 `stock_zh_a_hist` |

脚本启动时会自动探测哪个源可用，之后全程固定，不会每只股票都试错。

**Q：数据准确吗？**
行情数据与同花顺 iFinD 一致（同一交易所行情）。差异只在财务数据——本报告只用 PE/PB，取自实时快照。
技术指标全部由脚本自己计算，**比之前用 iFinD 自然语言筛选更可控**：之前出现过买点2 筛出 329 只、买点3 筛出 460 只这种过宽结果，现在条件写死在代码里，可复现、可审计、可微调。

**Q：本地能跑吗？**
能。`python screener.py` 即可。调试时可设 `MAX_CODES=100` 只处理前 100 只。

> ⚠️ **不要用 `MAX_CODES` 的结果当真实选股结论**。它是按**代码顺序**截取的，而代码穷举顺序是 600000→601999→603000→…，取前 80 只会得到清一色沪市主板老股，深市和科创板一只都进不来，结果严重失真。它只用于验证流程能否跑通。
> 想缩小范围又保持代表性，改用 `POOL_SIZE`（按成交额取头部，覆盖各板块活跃股），例如 `POOL_SIZE=300`。
> 非交易日想补跑，加 `FORCE_RUN=1`。
注意本机若装不了 akshare，多半是 `jsonpath` 这个依赖只有源码包导致 pip 构建失败，可先 `pip install --no-deps akshare beautifulsoup4 lxml requests curl_cffi html5lib xlrd urllib3 tqdm`，再补 `idna charset-normalizer certifi soupsieve webencodings six typing_extensions cffi pycparser py_mini_racer`。

**Q：本地跑说连不上行情接口？**
本机网络可能拦截东方财富域名，脚本会自动切到腾讯源，不影响结果。用 `python test_offline.py` 可以完全离线验证筛选逻辑是否正确（合成数据，不联网）。

**Q：想改筛选条件？**
直接改 `screener.py` 里的 `judge_buypoint()` 函数，push 上去即可，下次自动生效。

**Q：想改每类买点展示几只？**
改 `screener.py` 顶部的 `TOP_N_BY_BP`，当前是 `{1: 15, 2: 15, 3: 15}`——买点1/2 各展示 15 只带 K 线卡片；**买点3 展示 15 只简表**（不单列带 K 线的卡片，破线拉回假信号最多、不具备单独研判价值，故全部用轻量表格列出）。
`TOP_SAVE=40` 是写入 JSON 的条数，比展示数多，方便事后核对完整命中、也给备选区留货。
报告里会同时显示「展示 N 只（共命中 M 只）」。

**Q：想改观察期/回访区数量？**
`WATCH_DAYS`（观察期交易日数，默认 20）、`WATCH_EXPIRE_NATURAL`（对应的自然日上限，32）、`WATCH_DROP_PCT`（破位线，−10%）、`MAX_REVISIT`（回访区最多几只，6）、`ALT_N`（备选区每类列几只，12）。

**Q：想改亏损股的剔除门槛？**
`LOSS_PB_LIMIT`（默认 5，PE≤0 且 PB 超过它就硬剔除）、`LOSS_PENALTY`（默认 5 分，亏损但低 PB 的扣分）。

**Q：想改推送时间？**
改 `.github/workflows/daily.yml` 里的 `cron: '10 7 * * 1-5'`。
格式是 `分 时 日 月 周`，**时区是 UTC**，北京时间减 8 小时。
例如改到 14:45 → `45 6 * * 1-5`。
